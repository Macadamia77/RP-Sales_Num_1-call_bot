# handoff — 세션 마무리

다음 작업자가 `STATE.md`만 읽고 바로 이어갈 수 있게 만드는 것이 목표다.

## 절차

1. `git pull`로 최신 `STATE.md`를 받는다. 그 사이 다른 에이전트가 갱신했으면 그 내용 위에 덧붙인다.
2. `STATE.md` 맨 위 표를 고친다: 마지막 갱신(오늘 날짜), 마지막 작업자, 작업 브랜치, 현재 단계.
3. **진행 중**: 이번 세션에서 적었던 내 줄을 지운다. 끝내지 못했으면 지우지 말고 `(중단: <어디까지>)`를 붙인다.
4. **마일스톤 진행도**: `docs/spec.md` §1 완료 기준을 실제로 충족한 경우에만 ✅. 막혔으면 ⛔와 이유.
5. **다음 할 일**: 끝낸 항목은 지우고, 새로 생긴 할 일을 우선순위 순으로 넣는다.
6. **테스트 시나리오 현황**: 작성·통과한 시나리오 상태를 바꾼다.
7. **막힌 것 / 위험**: 새로 발견한 것을 추가하고, 해소된 것은 지운다.
8. **작업 내역** 맨 위에 항목을 추가한다:
   ```
   ### YYYY-MM-DD · <에이전트> · `<브랜치>`
   - 한 일:
   - 결정:
   - 다음:
   ```
   3~5줄 이내. 자세한 내용은 커밋에 맡긴다.
9. 결정이 확정됐다면 `record-decision` 절차도 함께 처리한다.
10. 커밋하고 푸시한다. 메시지 예: `[claude-A] handoff: M02 상태 머신 초안`

## 하지 말 것

- `AGENTS.md`의 불변 규칙을 이 과정에서 고치지 않는다.
- 작업 내역의 이전 항목을 지우거나 고치지 않는다. 병합 충돌이 나면 양쪽 항목을 모두 남긴다.
- 실제 전화번호·키·대화록 원본을 `STATE.md`에 적지 않는다.
