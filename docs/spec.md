# 상세 명세 (설계 v1.0 기준)

> 구현할 때 참고하는 상세 내용입니다. 원본은 `docs/design/ai-call-agent-guide.html`.
> 진행 상황(어디까지 했는지)은 여기 적지 않고 `STATE.md`에 적습니다.

## 1. 마일스톤 정의와 완료 기준

UI 구현량이 아니라 **완료 기준**이 일정의 기준이다.

| ID | 이름 | 내용 | 완료 기준 |
|---|---|---|---|
| M01 | 전화 연결 가능성 확인 | 공급사 계정·발신번호 준비, 본인 테스트 번호로 한 통 발신. 한국 연결, 표시 번호, 송·수신 음성 확인 | 실제 전화가 연결되고 양방향으로 소리가 들린다 |
| M02 | 텍스트로 대화 로직 검증 | 전화 없이 가상 상대 발화 입력. 번호 제공·정정·거절·다른 건물·다른 문의처 테스트, 상태 전이 점검 | 확인 근거 없이 성공 처리하지 않고, 예외 상황에서 정해진 단계로 이동한다 |
| M03 | 마이크로 음성 대화 구현 | STT·LLM·본인 목소리 TTS 연결. 짧은 대화, 숫자 낭독, 말 끊기, 긴 침묵 확인 | 생성 문장이 들리고, 상대 발화 시 재생을 멈추며, 끊긴 답변이 다시 나오지 않는다 |
| M04 | 실제 통화 한 건을 끝까지 연결 | 전화 API + 음성 루프 + 대화록·후보 번호·재확인 결과 DB 저장 | 통화 시작부터 종료·결과 조회까지 한 흐름으로 완료된다 |
| M05 | 관리 화면과 소규모 운영 | 목록 입력, 템플릿 선택, 실행·중단, 결과 검토, CSV. 모든 결과를 사람이 확인하고 오류 원인 분류 | 번호와 대화 근거를 빠르게 검토할 수 있고, 실패 이유가 구분된다 |
| M06 | 대기열과 동시 통화 확대 | 예약, 제한된 재시도, 동시 통화 수 증가, 공급사 한도·비용 상한 | 통화 간 대화가 섞이지 않고, 취소·중복 방지·사용량 집계가 유지된다 |

M02는 외부 계정 없이 시작할 수 있어 M01과 병행할 수 있다.

**MVP 범위:** 본인 음성 등록·미리 듣기 / 건물명·주소·수신번호·문의 목적 입력 / 템플릿 편집·텍스트 대화 테스트 / 동시 통화 1개, 발신·중단·종료 / 번호 추출·재확인·대화록 저장 / 결과 조회·근거 확인·CSV
**후속:** 동시 통화·예약 발신, 사람에게 넘기기, ARS·키패드(DTMF), 소개 번호 후속 발신, 실제 연결 검증, 여러 목소리·조직·권한

## 2. 통화 흐름

```
인사 → 건물 확인 → 번호 요청 → 후보 수집 → 번호 재확인 → 저장·종료
```

대화 예시:
```
AI   안녕하세요. {requester_name}님의 요청으로 연락드린 AI 전화 도우미입니다. {building_name} 관리사무소 전화번호를 여쭤봐도 될까요?
상대 어느 예시빌딩이요?
AI   {building_address}에 있는 예시빌딩 말씀드립니다.
상대 아, 거기는 공이, 일이삼사에 오육칠팔로 해 보세요.
AI   공 이 / 일 이 삼 사 / 오 육 칠 팔, 그 건물 관리사무소 번호가 맞을까요?   ← 코드가 만든 문장
상대 네, 맞아요.
AI   안내해 주셔서 감사합니다. 좋은 하루 보내세요.   → confirmed_by_source, reachability: not_tested
```

### 예외 처리
| 상황 | 처리 | 저장 결과 |
|---|---|---|
| 번호를 못 들음 | 필요한 부분만 다시 질문 ("국번 다음 네 자리만…") | 후보 유지, 확인 대기 |
| 건물이 다름 | 주소·건물명 한 번 더 확인, 불일치하면 종료 | 잘못된 문의처 |
| 모른다고 함 | 다른 문의처를 아는지 한 번만 묻고 종료 | 미확보 또는 소개 번호 |
| 다른 번호 소개 | 대상·용도 확인 후 후보로 저장 | 관리사무소 번호와 구분 |
| 나중에 전화 요청 | 요청 시간·사유 저장, 정책에 따라 처리 | 재통화 요청 |
| 거절·종료 요청 | 감사 인사 후 종료, 재시도 제외 | 거절, 재발신 제외 |
| 부재·사서함·ARS | MVP는 분류 후 종료, 불확실하면 검토 필요 | 부재 / 자동응답 / 불명 |
| 긴 침묵 | 한 번 확인 후 대기 제한 넘으면 종료 | 응답 없음 |

## 3. 번호 추출과 검증

1. 확정된 상대방 발화에서 후보를 찾는다 (발화 ID 기준).
2. 원문과 정규화 숫자를 분리한다. `"공이 일이삼사 오육칠팔"` → `"02-1234-5678"`. 앞자리 0 보존, 누락된 자리 채우지 않음.
3. 번호의 대상(관리사무소·부동산·다른 문의처·불명)과 형식을 확인한다. 형식 검사는 오타 검출용일 뿐 실사용 번호의 증거가 아니다.
4. 저장한 숫자로 **코드가** 낭독 문장을 만든다.
5. 상대의 확인/정정을 반영한다. "네, 맞아요"가 방금 읽은 번호에 대한 답인지 판단한다.
6. 최종 번호 + 제공 발화 + 낭독 발화 + 확인 발화를 연결해 저장한다.

**확인 상태 3단계**
| 상태 | 의미 |
|---|---|
| `candidate` | 들었지만 전체 숫자 또는 용도 미확인 |
| `confirmed_by_source` | 전체 번호를 다시 읽었고 상대가 맞다고 답함 (**MVP 성공 기준**) |
| `reachability_verified` | 그 번호로 걸어 관리사무소임을 확인 (후속) |

TTS 모델마다 전화번호 읽기가 다를 수 있으므로 저장용 숫자와 읽기용 문장을 분리하고 실제 전화에서 확인한다.

## 4. 데이터 구조

### LLM 구조화 응답
```json
{
  "intent": "provided_contact",
  "next_action": "request_number_readback",
  "say_text": null,
  "contact_candidate": { "raw_text": "공이 일이삼사 오육칠팔", "digits": "0212345678", "role": "management_office" },
  "evidence_utterance_ids": ["u_06"]
}
```
`next_action`은 허용 목록 enum. 서버가 후보·원문을 검증한 뒤 낭독 문장을 만든다.

### 통화 결과
```json
{
  "call_id": "call_example_001",
  "building": { "name": "예시빌딩", "address": "사용자가 입력한 건물 주소" },
  "recipient": { "name": "예시부동산", "number": "원래 전화를 건 번호" },
  "template_version": "management-contact-v1",
  "outcome": "number_confirmed_by_source",
  "contacts": [{
    "phone_raw": "공이 일이삼사 오육칠팔",
    "phone_normalized": "02-1234-5678",
    "contact_role": "management_office",
    "confirmation_status": "confirmed_by_source",
    "reachability_status": "not_tested",
    "provided_in_utterance": "u_06",
    "readback_in_utterance": "u_07",
    "confirmed_in_utterance": "u_08"
  }],
  "transcript_id": "transcript_example_001",
  "recording_ref": null,
  "callback_request": null,
  "do_not_retry": false,
  "review_status": "pending_review"
}
```

### 저장 단위
| 단위 | 주요 필드 |
|---|---|
| 목소리 | 소유 사용자, 공급사, voice_id, 등록·삭제 시각 |
| 템플릿 | 이름, 버전, 내용, 변경 시각 |
| 발신 작업 | 건물, 대상 번호, 예정 시각, 시도 횟수, 상태 |
| 통화 | 공급사 통화 ID, 시작·종료 시각, 결과, 종료 원인 |
| 발화 | 화자, 통화 기준 시각, 확정 텍스트, 재생·중단 상태 |
| 연락처 후보 | 원문, 숫자, 용도, 후보 버전, 확인 상태, 증거 발화 ID |

CSV에는 긴 대화록 대신 번호, 상태, 정보 제공처, 내부 통화 ID를 넣는다.

## 5. 템플릿

| 변수 | 의미 | 필수 |
|---|---|---|
| `requester_name` | 실제 요청자 이름 또는 조직명 | 필수 |
| `building_name` | 건물명 | 필수 |
| `building_address` | 동명 건물 구분용 주소 | 필수 |
| `recipient_number` | 전화할 점포·부동산 번호 | 필수 |
| `inquiry_purpose` | 상대가 물으면 설명할 실제 문의 목적 | 필수 |
| `recipient_name` | 점포명·부동산명 | 선택 |
| `voice_id` / `template_version` | 목소리, 템플릿 버전 | 필수 |

- **사용자가 수정하는 영역:** 인사 문구, 문의 목적, 설명 방식, 말투, 모를 때 후속 질문, 감사 인사. 저장할 때마다 새 버전, 통화마다 사용 버전 기록.
- **시스템이 고정하는 영역:** 허위 신분 금지, 번호 추측 금지, 확인 근거 검증, 종료 요청 처리, 발신 범위·시간·횟수 제한, 외부 도구 실행 권한.
- 템플릿 원문 예시는 설계 원본 §05 참고.

## 6. 내부 API (설계 예시)

| 경로 | 역할 |
|---|---|
| `POST /api/voices` | 본인 목소리 등록 작업 생성 → voice_id |
| `POST /api/templates` | 템플릿 버전 저장 |
| `POST /api/call-jobs` | 건물·수신번호·목적으로 발신 작업 생성 |
| `POST /api/call-jobs/{id}/cancel` | 대기 취소 / 진행 통화 종료 |
| `POST /webhooks/telephony` | 공급사 상태 알림 (서명·중복 확인) |
| `WS /media/{call_id}` | 공급사 규격 음성 연결 |
| `GET /api/calls/{id}` | 통화 결과와 근거 조회 |
| `GET /api/results.csv` | 결과 내보내기 |

### 실시간 처리 루프 (의사 코드)
```
발신 작업 시작: 중복 실행 잠금·취소 여부 확인 → 발신 → 공급사 통화 ID 저장 → 받으면 음성 스트림 연결
상대 말 시작: 현재 답변 생성 취소 → 재생 버퍼 비우기 → 이전 응답 ID 무효화
확정 발화 도착: 발화 저장 → (단계 + 템플릿 + 이력)으로 LLM 호출 → 구조화 결과·증거 ID 검증
              → 후보/정정 반영 → 재확인 필요하면 서버가 낭독 문장 생성, 아니면 허용된 LLM 답변
              → 새 응답 ID로 TTS 스트리밍 → 현재 ID와 일치하는 음성만 송출
통화 종료: STT·LLM·TTS 취소, 자원 해제 → 결과 한 번만 최종 저장 → 재시도 정책 / 검토 대상 분류
```

## 7. 공급사 관련 메모 (2026-09 기준, 변경 가능)

- Twilio: 발신번호는 계정 소유 번호 또는 검증된 번호여야 함. **한국 가이드상 국내 발신번호 표시가 보장되지 않음.** `<Connect><Stream>`으로 양방향 스트림, 송출 음성은 헤더 없는 8kHz μ-law base64. `clear` 메시지로 재생 버퍼 비움. 양방향 Media Streams의 DTMF는 수신 방향만.
- ElevenLabs IVC: 깨끗한 단일 화자 녹음 약 1~2분 권장, 한국어 모델 있음. 일부 모델은 전화번호 정규화가 기대와 다를 수 있음.
- OpenAI Custom voices: 이용 자격 있는 고객 한정, 동의 녹음 필요. OpenAI TTS는 AI 생성 음성임을 명확히 알리도록 요구.
- 공급사 선정 순서: 국내 통화 조건 확인 → 본인 테스트 번호 연결 → 양방향 음성 → 실제 발신번호 확인 → 음성 에이전트 결합.

## 8. 테스트 시나리오 정의

| ID | 상황 | 기대 결과 |
|---|---|---|
| T01 | 정상적으로 전체 번호 제공 | 자리별 낭독 후 확인 발화와 번호를 연결해 저장 |
| T02 | 지역번호 없이 뒤 숫자만 | 지역번호 재질문, 임의로 채우지 않음 |
| T03 | "마지막은 팔이 아니라 구예요" | 정정, 이전 확인 해제, 다시 읽음 |
| T04 | 부동산·관리사무소 번호 함께 제공 | 번호별 용도 분리, 관리사무소 번호 확인 |
| T05 | 재확인 중 통화 끊김 | 후보로 저장, 확인 완료 아님 |
| T06 | 낭독 도중 상대가 말함 | 재생·생성 중단, 늦은 음성 조각 폐기 |
| T07 | 거절 / 다시 전화 말라 | 종료, 자동 재발신 제외 |
| T08 | LLM 지연 / 음성 연결 장애 | 제한에 따라 처리·종료, 실패 원인 기록 |
| T09 | 같은 작업·웹훅 두 번 도착 | 발신·최종 저장 중복 없음 |
| T10 | 다른 지시·다른 번호 발신 요구 | 발언으로 기록, 서버 발신 범위 유지 |

**지표:** 번호 정확 일치율, 잘못된 성공 처리 건수, 재확인 증거율, 업무 완료율 / 응답 지연, 말 끊기 지연, 침묵·반복, 연락처 1건 확보 비용(실패·재시도 포함 총비용 ÷ 확보한 고유 연락처 수, 성공 0건이면 "산정 불가"). 목표값은 직접 측정한 뒤 정한다.
